# WMS 물품관리자 업무 프로토콜

> 물품관리자의 물품 대여·반납 및 재고 관리 방법을 정리한 실무 문서입니다.  
> 기준일: 2026-09-14 · 대상 시스템: WMS 및 Scenario Manager(SM)

## 문서의 목적

물품관리자의 최우선 목표는 회사 물품의 위치, 수량, 대여자와 상태가 실제 현황과 일치하도록 유지하는 것입니다. 모든 업무는 다음 원칙을 따릅니다.

1. 실물을 먼저 확인하고 WMS를 처리합니다.
2. 대여자, 물품, 수량, 위치를 처리 전에 한 번 더 확인합니다.
3. 재고를 직접 수정할 때는 반드시 구체적인 사유를 남깁니다.
4. 파손·분실·소모는 일반 반납과 구분하여 기록합니다.
5. 화면에서 성공 메시지가 표시되고 목록이 갱신된 것까지 확인해야 처리가 끝난 것입니다.

# 📜 업무 수행 방법

## 대여 물품 구조

### 실내 번호 구역

- `000000 ~ 000059`: Bottle, Coke, 소형 수납함, 구두 등
- `000060 ~ 000119`: 레고, 의류 및 수건
- `000120 ~ 000185`: 멀티탭·콘센트, 실험용 용기, Trash Can, A4 Paper 등
- `000186 ~ 000251`: 필기구
- `100000 ~ 100023`: 그릇, 트레이 및 대형 Object
- `100024 ~ 100026`: 얼음 및 뽁뽁이

### 랙 구역

- A~B 랙: 리빙 박스
- C~D 랙: 로보티큐 물품
- E 랙: 공구 및 LAN 선
- F 랙: 볼트·너트, USB 선, 멀티탭
- G~I 랙: 컴퓨터 부품, HDMI·파워 선, 로보티큐 팔 부품
- J 랙: 기타 물품 및 기업용 시나리오 물품

> 번호와 랙 구성이 실제 배치와 다르면 임의로 판단하지 말고, 실물 라벨과 WMS 위치를 대조한 뒤 관리자에게 보고합니다.

## 로그인과 화면 구분

WMS 첫 화면에는 대여자 로그인과 관리자 로그인이 구분되어 있습니다.

- **대여자 로그인**: 이름·소속·사번·층·좌석을 입력합니다. 일반 직원이 물품을 조회하고 대여·반납할 때 사용합니다.
- **관리자 로그인**: 재고, 대여 확인, 반납, 로그, 설정 및 DB 관리에 사용합니다.
- 로그인 정보는 창을 닫기 전까지 유지되며 4시간 동안 동작이 없으면 자동 로그아웃됩니다.
- ConfigDS 사용자는 등록 명부와 이름을 대조합니다. 동명이인 또는 미등록 안내가 나오면 관리자 설정에서 계정을 확인합니다.
- 모바일에서는 조회·관리 일부만 지원하며, 일반 대여 신청과 반납 처리는 PC 사용을 원칙으로 합니다.

## 1️⃣ 대여하기

### 1-1. 대여자의 셀프 대여

1. 대여자는 **대여자 로그인**에서 본인의 이름, 소속, 사번과 좌석을 입력합니다.
2. 대여 메뉴에서 분야를 선택합니다.
   - 시나리오 물품 대여
   - COS 물품 대여
   - 테이블보 대여
3. 물품명, ID 또는 위치로 검색하고 사진과 위치를 확인합니다.
4. 필요한 수량만 장바구니에 담습니다.
5. 장바구니에서 물품·수량·사용 목적을 확인하고 신청합니다.
6. 재고 부족, 대여 잠금 또는 대여 종류 제한 안내가 나오면 억지로 진행하지 않습니다.

### 1-2. SID 대여

1. **시나리오 물품 대여 → SID 대여**로 이동합니다.
2. `S`로 시작하는 시나리오 ID를 입력합니다.
3. 조회된 필요 물품과 필요 수량, 현재 재고를 확인합니다.
4. **필요 물품 담기**를 사용해 장바구니에 담습니다.
5. 재고가 없는 물품은 담기지 않으므로 누락 목록을 확인하고 담당자에게 알립니다.
6. 시나리오에 없는 물품을 추가하면 해당 신청은 일반 대여가 섞인 신청으로 처리될 수 있으므로 목적을 확인합니다.

### 1-3. 일반 시나리오 물품 대여

1. **시나리오 물품 대여 → 일반 대여**로 이동합니다.
2. ID·물품명·위치로 검색합니다.
3. 사진, 위치, 재고 및 주의 배지를 확인한 뒤 장바구니에 담습니다.
4. 종류가 나뉜 물품은 반드시 실제로 가져갈 종류를 선택합니다.
5. `특정 업체 request용`, `개인 물품` 표기가 있으면 용도와 사용 가능 여부를 먼저 확인합니다.

### 1-4. 관리자의 대여 확인

시나리오·일반 물품은 대여 신청 직후 바로 확정되지 않고 관리자의 실물 확인을 거칠 수 있습니다.

1. 관리자 모드에서 **대여 & 반납 관리 → 대여**를 엽니다.
2. 신청자를 선택하고 실물과 화면의 물품·수량을 대조합니다.
3. 물품을 선택하면 사진 미리보기로 다시 확인한 뒤 장바구니에 담습니다.
4. `종류 상관없음` 신청은 실제 지급한 종류를 선택합니다.
5. 장바구니의 작업이 **확인**인지 검토하고 처리합니다.
6. 처리 후 해당 신청이 대여 확인 목록에서 사라지고 반납 대상에 나타나는지 확인합니다.

### ⭐ 대여 팁

- 같은 물품명이 여러 위치에 있으면 이름이 아니라 **ID와 위치**를 기준으로 확인합니다.
- 재고 수량보다 많이 담을 수 없습니다. 실물은 있는데 재고가 0이면 먼저 재고 오차를 해결합니다.
- 대여 종류 제한은 수량이 아니라 서로 다른 물품의 **가짓수** 기준입니다.
- 특정 인원에게 페널티가 적용된 경우 제한 종류 수, 사유와 만료일이 대여 화면에 표시됩니다.
- 전체 또는 특정 유닛의 대여가 잠겨 있어도 반납은 가능합니다.

## 2️⃣ 반납하기

### 2-1. 시나리오·일반 물품 반납

1. 반납 테이블에 들어온 실물의 ID, 수량과 상태를 확인합니다.
2. 관리자 모드에서 **대여 & 반납 관리 → 반납**을 엽니다.
3. 대여자 또는 물품으로 검색한 뒤 대여자를 선택합니다.
4. 실제 들어온 물품만 장바구니에 담고 수량을 맞춥니다.
5. 장바구니의 작업이 **반납**으로 되어 있는지 확인합니다.
6. 정상 반납이라면 반납 사진을 촬영합니다.
7. 최종 확인 화면에서 대여자·물품·수량·처리 방식을 검토하고 처리합니다.
8. 완료 후 미반납 목록과 물품의 대여 중 수량이 줄었는지 확인합니다.

### 2-2. 일부 수량 반납

- 여러 개를 빌린 기록에서 일부만 들어온 경우 실제 수량만 입력합니다.
- 남은 수량은 기존 대여 기록에 계속 남아 있어야 합니다.
- 전량 반납으로 잘못 처리했다면 재고를 임의로 수정하지 말고 대여·반납 로그와 묶음 상세를 확인합니다.

### 2-3. 반납 후 즉시 재대여

같은 사람이 같은 물품을 계속 사용하되 대여일만 갱신해야 할 때 사용합니다.

1. 반납 장바구니에 물품을 담습니다.
2. **반납 후 다시 대여**를 켭니다.
3. 반납 사진과 수량을 확인하고 처리합니다.
4. 기존 기록이 반납 완료되고 새 대여 기록이 즉시 생성됐는지 확인합니다.

### 2-4. 다른 사람에게 양도

1. 반납 장바구니에 양도할 물품을 담습니다.
2. **다른 사람에게 양도**를 켭니다.
3. 새 대여자의 이름·소속·사번을 정확히 입력합니다.
4. 동명이인이 있을 수 있으므로 이름만 확인하지 않습니다.
5. 처리 후 기존 대여자는 반납 완료, 새 대여자는 대여 중으로 표시되는지 확인합니다.

### 2-5. 파손 반납

1. 해당 장바구니 줄에서 **파손**을 선택합니다.
2. 파손 수량을 입력합니다.
3. 불량 유형, 현상, 조치 내용, 원인 제공자와 사진을 기록합니다.
4. 대체품을 지급하고 계속 대여시키는 경우 지급한 종류와 수량을 별도로 확인합니다.
5. 처리 후 반납 기록, 불량 로그와 재고 차감이 모두 반영됐는지 확인합니다.

### 2-6. COS 물품 반납·소모

- 다시 사용할 수 있는 물품은 **반납**으로 처리하여 재고로 돌려놓습니다.
- 사용하면서 없어지는 자재는 **소모**로 처리합니다.
- 소모품을 반납으로 처리하면 재고가 부풀고, 반납품을 소모로 처리하면 재고가 줄어드므로 반드시 구분합니다.

### ⭐ 반납 팁

- 실제 반납되지 않은 물품을 화면에서 먼저 처리하지 않습니다.
- 실물 픽업이 취소된 신청은 일반 반납과 다르게 사진이 필요하지 않을 수 있습니다.
- 사진 촬영 화면이 열리지 않으면 서버 웹캠 연결과 카메라 스트림을 확인합니다.
- 처리 중에는 새로고침을 연속으로 누르지 말고 완료 또는 실패 메시지를 기다립니다.

## 3️⃣ 물품 변경 및 재고 관리

### 3-1. 재고 수량 변경

1. 관리자 모드에서 물품 관리 화면으로 이동합니다.
2. 대상 물품을 ID·이름·위치로 검색합니다.
3. **재고 변경** 아이콘을 누릅니다.
4. 현재 재고와 대여 중 수량을 확인합니다.
5. 새 재고를 입력하고 구체적인 변경 사유를 작성합니다.
6. 변경 전후 차이를 확인한 뒤 **재고 변경하기**를 누릅니다.
7. 성공 메시지와 변경 이력을 확인합니다.

권장 사유 예시:

- `신규 입고 10개 반영`
- `2026-09-14 실사 결과 2개 부족`
- `파손 1개 폐기`
- `중복 등록 정정`

> **대여 중 수량 직접 변경**은 대여·반납 기록과 별개입니다. 실사 결과와 기록이 명백하게 어긋났을 때만 사용하고, 변경 전 대여자 상세와 전체 이력을 확인합니다.

### 3-2. 종류가 있는 물품

- 종류별 수량을 각각 입력합니다.
- 총재고는 `종류별 재고 합계 + 미확인 수량`으로 자동 계산되므로 총재고를 직접 맞추지 않습니다.
- 종류 도입 전에 대여된 물품이 돌아오면 **미확인**에 들어갈 수 있습니다. 실물을 확인한 뒤 올바른 종류에 배분합니다.

### 3-3. 위치·정보 변경

1. 대상 물품의 편집 화면을 엽니다.
2. 이름, 위치, 서브 분류, 특이사항, 검색어, 구매 링크와 사진을 확인합니다.
3. 필요한 필드만 수정합니다.
4. 저장 후 목록 검색과 실제 선반 라벨이 일치하는지 확인합니다.

### 3-4. 보관함 사용

- 당분간 사용하지 않지만 기록을 보존해야 하는 물품은 삭제하지 말고 보관함으로 이동합니다.
- 보관 처리된 물품은 일반 목록과 대여 카탈로그에서 숨겨집니다.
- 다시 사용할 때 보관함에서 꺼냅니다.
- 대여 중인 물품을 보관 처리하면 반납 기록은 유지되지만 사용자 목록에서 보이지 않을 수 있으므로 가급적 반납 후 처리합니다.

## 4️⃣ 오브젝트 등록 및 설정

### 4-1. 시나리오 오브젝트 등록

1. 관리자 모드에서 **물품 관리 → 시나리오 물품**으로 이동합니다.
2. **물품 추가**를 누릅니다.
3. 물품명, 위치, 재고, 사진, 특이사항 및 필요한 치수를 입력합니다.
4. SM 연동 상태가 정상이면 ID는 SM에서 자동 발급됩니다.
5. SM 연동이 끊긴 경우 임의 번호를 만들지 말고 연동 상태를 먼저 확인합니다.
6. 저장 후 WMS 목록과 SM에서 같은 ID·재고로 보이는지 확인합니다.

> SM 오브젝트는 잘못 생성하면 완전 삭제가 어려울 수 있습니다. 저장 버튼을 연속으로 누르지 않습니다.

### 4-2. 사진과 실제 크기

- 대표 사진은 물품 식별이 쉽도록 정면 또는 사용 상태가 보이게 촬영합니다.
- 추가 사진에는 측면, 구성품, 라벨과 파손되기 쉬운 부분을 남깁니다.
- 실제 크기는 폭·깊이·높이와 형태를 입력합니다.
- 종류별 크기가 다르면 물품 전체 치수 대신 종류별 치수를 입력합니다.
- 실제 크기 보기의 Left·Center·Right는 고정 시점 비교용입니다.

### 4-3. 재고 실사와 불일치 진단

1. 물품 상세에서 대여자, 재고 실사, 전체 이력을 확인합니다.
2. 실물 선반 수량을 세어 **실사 수량**으로 기록합니다.
3. 시스템 재고와 다르면 바로 숫자만 고치지 말고 진단 기능과 대여·반납 이력을 확인합니다.
4. 중복 대여, 누락 반납, 파손·소모 미처리 여부를 먼저 찾습니다.
5. 원인을 찾을 수 없을 때만 실사 사유를 남기고 재고를 조정합니다.

### 4-4. SM 동기화 확인

- WMS가 물품 수량과 대여 상태의 기준 장부이며 SM으로 동기화됩니다.
- SM의 `1010` 표시는 실제 대여자가 아니라 동기화 처리 계정일 수 있습니다.
- 대여·반납 직후 수 초에서 수 분의 반영 시간이 발생할 수 있습니다.
- 현재 시스템은 정기 변화 감지와 30분 전체 대조로 누락을 복구합니다.
- 불일치가 계속되면 물품 ID, WMS 대여 수량, SM 대여 수량과 발생 시각을 기록해 개발 담당자에게 전달합니다.

---

## 5️⃣ COS 물품 관리

### 5-1. 신규 입고 및 품목 등록

1. 기존에 같은 품목이 있는지 이름과 위치로 먼저 검색합니다.
2. 같은 품목이면 **재고 변경**으로 입고 수량을 더합니다.
3. 신규 품목이면 **품목 추가**를 누릅니다.
4. 새 선반 위치를 만들거나 기존 위치를 선택합니다.
5. 품목명, 위치, 서브 분류, 특이사항, 검색용 한글 별칭, 재고와 사진을 입력합니다.
6. 소모품이면 **대여 시 자동 소모 처리** 여부를 정확히 설정합니다.
7. 저장 후 실제 라벨과 WMS 위치를 대조합니다.

### 5-2. 볼트 길이 측정 및 기록

- **M**: 볼트 몸통의 지름
- `x` 뒤 숫자: `볼트 총 길이 - 볼트 머리 길이`
- 측정 단위를 통일하고 동일 규격이 이미 등록돼 있는지 검색한 뒤 추가합니다.

### 5-3. 여러 물품 위치 이동

1. 대상 위치 또는 검색어로 목록을 좁힙니다.
2. 선택 모드에서 이동할 물품만 선택합니다.
3. 위치 일괄 변경을 실행합니다.
4. 새 위치의 실물 배치와 화면 결과를 다시 확인합니다.

---

## 6️⃣ 테이블보 관리

테이블보는 일반 시나리오 물품과 달리 담당자 확인 없이 사용자가 직접 대여하고 직접 반납합니다.

### 6-1. 사용자 대여·반납

- 로그인할 때 선택한 층이 기본 필터로 적용됩니다.
- 다른 층의 테이블보는 **전체** 또는 해당 층 필터를 눌러야 보입니다.
- 사진, 번호, 무늬 분류와 남은 수량을 확인한 뒤 대여합니다.
- 재고가 0이면 현재 대여자의 이름과 좌석을 확인할 수 있습니다.
- 반납은 **테이블보 반납**에서 본인의 대여 기록을 선택해 직접 처리합니다.

### 6-2. 관리자 등록·편집

1. **테이블보 관리 → 테이블보 목록**으로 이동합니다.
2. 새 테이블보는 위치, 재고, 펼친 크기, 사진, 무늬 분류, 링크와 메모를 입력합니다.
3. 이름은 직접 입력하지 않으며 `TC-0000` 형식의 번호가 자동 발급됩니다.
4. 접은 상태로 측정했다면 펼친 크기로 환산해 저장합니다.

### 6-3. 일괄 작업

- **위치 변경**: 선택한 항목의 위치만 변경합니다.
- **분류 지정**: 선택한 항목의 무늬 분류만 변경합니다.
- **다른 층으로 복사**: 사진·크기·분류·재고를 복사하되 새 번호로 생성합니다.
- **보관함으로**: 일반 목록과 대여 화면에서 숨깁니다.
- **삭제**: 되돌릴 수 없습니다. 잘못 등록한 중복 또는 실물이 완전히 없어진 경우에만 사용합니다.

> 대여 중인 테이블보를 삭제하면 반납 처리가 막힐 수 있습니다. 삭제 전 **대여 이력 → 대여 중**을 반드시 확인합니다.

### 6-4. 분류 관리

- 무늬 분류의 이름, 이모지, 색상과 순서를 관리할 수 있습니다.
- 분류 이름을 바꾸면 기존 테이블보는 새 이름을 따라갑니다.
- 분류를 삭제하면 해당 분류를 쓰던 테이블보가 미분류로 돌아갑니다.

---

## 7️⃣ 불량 로그 등록

1. 관리자 모드에서 **불량로그**를 엽니다.
2. 기존 물품을 검색하거나 필요하면 품목명을 직접 입력합니다.
3. 수량과 불량 유형을 선택합니다.
4. 불량 현상, 원인과 조치 내용을 구체적으로 적습니다.
5. 가능한 경우 사진을 첨부하거나 서버 카메라로 촬영합니다.
6. 등록 후 불량 로그 목록에서 저장 여부를 확인합니다.

불량 유형 예시:

- 파손
- 분실
- 작동 불량
- 오염
- 구성품 누락

> 일반 불량 로그 등록과 파손 반납은 목적이 다릅니다. 대여 중 물품이 파손되어 돌아온 경우에는 먼저 반납 화면의 **파손 반납** 흐름을 사용합니다.

## 8️⃣ 설정 및 DB 관리

### 대여/반납 설정

- 기본 대여 가능 종류 수 제한
- 개인별 페널티: 이름, 제한 종류 수, 사유, 만료일
- 전체 또는 특정 유닛 대여 잠금
- 잠금 중에도 반납은 계속 가능

### DB 설정

- DB 조회: 운영 데이터 확인용
- SID 편집: 시나리오 정의 확인 및 수정
- XLSX 입력/추출: DB 백업·이관용

> XLSX 입력은 많은 데이터를 한꺼번에 변경할 수 있습니다. 실행 전 DB를 XLSX로 추출하고 원본 파일을 별도로 보관합니다. DB를 직접 수정하기 전에 일반 관리 화면에서 가능한 작업인지 먼저 확인합니다.

# 🚨 이슈 대응

## 화면에 처리 성공이 떴지만 목록이 그대로인 경우

1. 15~20초 자동 갱신을 기다립니다.
2. 화면의 새로고침 버튼을 한 번 누릅니다.
3. 대여·반납 로그 또는 물품 전체 이력에서 실제 저장 여부를 확인합니다.
4. 브라우저 새로고침을 반복하거나 같은 처리를 다시 제출하지 않습니다.

## 재고와 대여 중 수량이 맞지 않는 경우

1. 물품 상세의 대여자 목록과 전체 이력을 확인합니다.
2. 신청 묶음 상세에서 일부 반납 여부를 확인합니다.
3. 재고 실사를 기록하고 불일치 진단을 실행합니다.
4. 원인 확인 없이 대여 중 수량을 직접 수정하지 않습니다.

## WMS와 SM이 맞지 않는 경우

1. `scenario-manager/` 접속 여부를 확인합니다.
2. WMS 연결 상태와 최근 동기화 시각을 확인합니다.
3. 최대 30분의 전체 대조 시간을 기다립니다.
4. 계속 다르면 대상 물품 ID와 양쪽 수량을 개발 담당자에게 전달합니다.

## 사진 저장이 실패한 경우

1. 카메라 스트림과 실물 위치를 그대로 유지합니다.
2. 화면의 재시도를 사용합니다.
3. 처리 완료 여부를 로그에서 확인하기 전 같은 반납을 새로 시작하지 않습니다.

## 잘못 처리한 경우

- 기록을 감추기 위해 삭제하거나 숫자를 임의로 맞추지 않습니다.
- 물품 ID, 시각, 잘못 처리한 내용과 올바른 내용을 즉시 기록합니다.
- 대여·반납 로그와 재고 변경 이력을 근거로 복구합니다.
